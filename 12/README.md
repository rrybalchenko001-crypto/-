
# Лабораторная работа №12. Итоговый проект

**Вариант 8 — план туристических маршрутов**

- `amount` — длина маршрута в целых километрах.
- `completed` — пройден ли маршрут (`true` / `false`).

## Назначение

Консольная программа позволяет вести список туристических маршрутов, искать их, менять статус прохождения, удалять записи и получать статистику.

## Требования

Python 3.9 или новее. Дополнительные библиотеки не нужны.

## Структура проекта

- `main.py` — меню и взаимодействие с пользователем.
- `logic.py` — проверка данных, добавление, поиск, изменение статуса, удаление и статистика.
- `storage.py` — чтение и запись JSON.
- `data.json` — исходные записи.
- `test_logic.py` — автоматические тесты.

## Запуск

Откройте терминал в папке проекта и выполните:

```bash
python main.py
```

## Запуск тестов

```bash
python -m unittest -v
```

Тесты проверяют добавление записи, поиск без учёта регистра, изменение статуса, удаление без повторного использования ID, статистику и обработку ошибочных данных.

## Формат записи JSON

Каждая запись содержит ровно пять полей:

```json
{
    "id": 1,
    "title": "Прогулка по набережной",
    "category": "Пеший",
    "amount": 4,
    "completed": true
}
```

Правила:
- `id` — положительное целое число, уникальное в списке;
- `title` и `category` — непустые строки;
- `amount` — неотрицательное целое число (километры);
- `completed` — логическое значение `true` или `false`.

Новый ID определяется как максимальный существующий ID плюс один. Поэтому удалённые идентификаторы не используются повторно.

## Реализованные возможности

1. Циклическое консольное меню и корректный выход.
2. Просмотр и добавление маршрутов.
3. Поиск по названию и категории без учёта регистра.
4. Изменение статуса прохождения по ID.
5. Подтверждение удаления по ID.
6. Статистика: количество маршрутов, количество пройденных и непройденных маршрутов, общая длина и длина пройденных маршрутов.
7. Загрузка и сохранение JSON в кодировке UTF-8.
8. Проверка структуры и типов данных, уникальности ID и пустых полей.
9. Обработка ошибочного ввода, неизвестных ID и ошибок чтения/сохранения.
10. Автоматические тесты основных функций.

## Проверка сценариев

После запуска можно проверить:
- просмотр четырёх начальных записей;
- поиск слова `пеший`;
- изменение статуса маршрута;
- отмену и подтверждение удаления;
- добавление записи после удаления: новый ID не повторяет удалённый;
- сохранение, закрытие и повторный запуск программы.
